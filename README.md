# 📡 Shorts Radar — رادار شورتز

یک مینی‌اپ موبایل‌اول، فارسی، راست‌چین و تیره برای کشف **ترندهای مستند در نمونهٔ دادهٔ یوتیوب**، تخمین زمان انتشار و ساخت سناریوهای ۱۰ تا ۱۵ ثانیه‌ای.

**بدون فریم‌ورک، بدون دیتابیس، بدون وابستگی npm، بدون نیاز به خرید اشتراک.** تمام UI و CSS و JS مرورگر در `index.html` است؛ تحلیل در یک تابع Serverless انجام می‌شود. نتیجه و تنظیمات فقط در `localStorage` مرورگر ذخیره می‌شوند. هیچ اتصال به حساب یوتیوب و هیچ آپلود خودکاری وجود ندارد.

> رایگان یعنی قابل اجرا در سهمیه‌های رایگان: YouTube Data API، میزبانی شخصی Vercel Hobby و GitHub. هیچ سرویس پرداختی لازم نیست. سهمیه‌ها، شرایط استفاده و دسترسی منطقه‌ای ممکن است تغییر کنند؛ استفادهٔ نامحدود رایگان نیست. Gemini اختیاری است و بدون آن، تمام امکانات اصلی با قالب فارسی کار می‌کنند. برای نسخهٔ پایه Billing فعال نکنید و پلن پولی نخرید.

## واقعیت مهم دربارهٔ خروجی

- YouTube Data API v3 برچسب قطعی «این ویدیو Shorts است» یا نسبت ابعاد قابل اتکا برای تمام ویدیوها نمی‌دهد. برنامه **کاندیداهای ۱ تا ۱۸۰ ثانیه‌ای** را تحلیل می‌کند؛ کوتاه بودن به‌تنهایی تضمین Shorts بودن نیست.
- عنوان، تگ و هشتگ دادهٔ کاربران‌اند، نه خبر تأییدشده. این اپ صحت یک ادعای ویدیو را تأیید نمی‌کند. لینک‌های «مدرک» فقط شاهد استفاده از موضوع و آمار ویدیو هستند.
- تایم طلایی **همبستگی زمان انتشار ویدیوهای موفق در همین نمونه** است، نه ساعت آنلاین بودن مخاطبان کانال شما و نه تضمین وایرال شدن.
- بازار و `relevanceLanguage` فیلتر قطعی کشور سازنده یا زبان همهٔ نتایج نیستند. چارت `mostPopular` هم فهرست جامع تمام Shorts نیست.
- ایده‌ها پیشنهاد ساخت محتوای تازه‌اند، نه خلاصهٔ دیده‌شده یا تأییدشدهٔ ویدیو. قبل از ساخت، موضوع، مجوز صدا و صحت متن را بررسی کنید.

## راه‌اندازی کامل فقط با گوشی

مرورگر Chrome یا Safari کافی است؛ اگر پنل‌های سرویس‌ها خوب دیده نمی‌شوند، از منوی مرورگر **Desktop site / درخواست وب‌سایت دسکتاپ** را فعال کنید.

### ۱. ساخت کلید رایگان YouTube Data API v3 (اجباری)

1. وارد [Google Cloud Console](https://console.cloud.google.com/) شوید و با حساب گوگل وارد شوید.
2. از انتخاب‌گر پروژه بالا، **New Project** را بزنید و پروژه‌ای مثل `Shorts Radar` بسازید.
3. به **APIs & Services → Library** بروید؛ `YouTube Data API v3` را جست‌وجو و **Enable** کنید.
4. به **APIs & Services → Credentials → Create credentials → API key** بروید.
5. کلید را کپی و خصوصی نگه دارید. برای این اپ نیازی به OAuth، رمز حساب یوتیوب یا پرداخت نیست.
6. روی کلید بزنید؛ در **API restrictions**، گزینهٔ **Restrict key** و فقط **YouTube Data API v3** را انتخاب و ذخیره کنید.
7. کلید روی سرور Vercel استفاده می‌شود؛ محدودیت **HTTP referrers** مخصوص کلیدهای مرورگر است و اینجا باعث خطای 403 می‌شود. محدودیت IP هم بدون IP خروجی ثابت Vercel مناسب نیست. کلید را محدود به API کنید و برای محافظت از endpoint از `APP_PASSWORD` استفاده کنید.
8. در **APIs & Services → YouTube Data API v3 → Quotas** سهمیه را بررسی کنید (سهمیهٔ رایج اولیه: ۱۰٬۰۰۰ واحد روزانه).

**کلید را هیچ‌وقت داخل `index.html`، مخزن GitHub یا عکس عمومی نگذارید.** فقط در Environment Variables سرور قرار می‌گیرد.

### ۲. کلید Gemini (کاملاً اختیاری)

1. به [Google AI Studio](https://aistudio.google.com/apikey) بروید.
2. در صورت دسترسی منطقه‌ای/حساب، **Create API key** را بزنید و کلید را بگیرید.
3. فقط از مدل/سهمیهٔ **Free tier** موجود برای حساب استفاده کنید؛ فعال کردن Billing لازم نیست.
4. اگر نمی‌خواهید، دسترسی ندارید یا سهمیه رایگان تمام شده، این مرحله را رد کنید. اپ با **قالب فارسی ۱۲ ثانیه‌ای ۵ بیتی** کار می‌کند.
5. مدل پیش‌فرض طبق پیکربندی اپ `gemini-2.0-flash` است. اگر این مدل برای حساب شما قدیمی/غیرفعال شده، `GEMINI_MODEL` را با نام دقیق یک مدل رایگان قابل دسترس در AI Studio تنظیم کنید. خطا یا نبود مدل، تحلیل را خراب نمی‌کند و فقط ایده‌ها قالبی می‌شوند.

فقط آمار تجمعی و نام موضوع برای ساخت ایده به Gemini ارسال می‌شود؛ رمز اپ، کلید یوتیوب، عنوان/توضیح کامل ویدیوها و تنظیمات ذخیره‌شدهٔ مرورگر ارسال نمی‌شوند. اگر دربارهٔ شرایط داده‌های Free tier نگرانی دارید، کلید Gemini را تنظیم نکنید.

### ۳. فایل‌ها را از گوشی در GitHub قرار دهید

اگر این مخزن را دارید، می‌توانید **Fork** کنید؛ اگر کپی مستقل می‌خواهید:

1. وارد [GitHub](https://github.com/) شوید؛ **New repository** را بزنید، یک نام مثل `shorts-radar` انتخاب و مخزن را ایجاد کنید. مخزن عمومی یا خصوصی هر دو قابل استفاده‌اند.
2. از **Add file → Upload files** فایل‌ها را آپلود کنید. در گوشی ممکن است نمای دسکتاپ لازم شود.
3. فایل‌های `index.html`، `manifest.json`، `icon.svg`، `package.json`، `vercel.json` و `README.md` باید در **ریشهٔ مخزن** باشند؛ نه پوشهٔ تو در تو.
4. برای ساخت پوشهٔ API از **Add file → Create new file** استفاده و نام را دقیقاً `api/analyze.js` وارد کنید؛ کد فایل را بچسبانید و **Commit changes** را بزنید. یا کل پوشهٔ `api` را از فایل‌منیجر آپلود کنید.
5. برای اجرای محلی/تست، `dev.mjs` و پوشهٔ `tests` نیز در مخزن موجودند؛ برای دیپلوی به ابزار ساخت یا ترمینال گوشی نیاز نیست.
6. `.env` را آپلود نکنید. `.env.example` فقط فهرست نام متغیرهاست، نه محل کلید واقعی.

### ۴. Import در Vercel (پلن رایگان شخصی)

1. وارد [Vercel](https://vercel.com/) شوید و با GitHub متصل شوید.
2. **Add New → Project → Import Git Repository** را بزنید و همین مخزن را انتخاب کنید. در صورت نیاز دسترسی Vercel به مخزن را در GitHub تأیید کنید.
3. **Framework Preset = Other**، **Root Directory = ریشهٔ مخزن**.
4. **Build Command** و **Output Directory** را override نکنید؛ خالی/پیش‌فرض بگذارید. این پروژه build ندارد. `npm run dev` فرمان production نیست.
5. **Node.js Runtime** را روی یک نسخهٔ پشتیبانی‌شدهٔ Vercel (مثلاً ۲۲ یا ۲۴) بگذارید؛ کد با Node 18+ و `fetch` داخلی نوشته شده است. نسخهٔ ۱۸ ممکن است دیگر در Vercel قابل انتخاب نباشد.
6. در بخش **Environment Variables** متغیرهای جدول بعد را وارد کنید.
7. **Deploy** را بزنید. آدرس رایگان `…vercel.app` کافی است؛ دامنهٔ پولی لازم نیست.
8. اگر متغیرها را بعداً تغییر دادید، از **Deployments → … → Redeploy** استفاده کنید. تغییر متغیر بدون دیپلوی جدید، روی دیپلوی قبلی اعمال نمی‌شود.
9. از **Settings → Git** مطمئن شوید اتصال GitHub فعال و Production Branch همان شاخهٔ حاوی فایل‌های شماست. هر تغییر بعدی در شاخهٔ متصل، دیپلوی جدید می‌سازد.

Vercel Hobby برای استفادهٔ شخصی/غیرتجاری و در حدود محدودیت‌های پلن است؛ برای استفادهٔ تجاری شرایط جاری سرویس را بررسی کنید. برای این نسخه دامنه، دیتابیس، Cron، Analytics پولی یا اشتراک AI لازم نیست.

### ۵. متغیرهای محیطی

| نام | الزامی؟ | مقدار |
|---|---|---|
| `YOUTUBE_API_KEY` | بله | کلید YouTube Data API v3 |
| `GEMINI_API_KEY` | خیر | کلید AI Studio؛ خالی = قالب فارسی |
| `GEMINI_MODEL` | خیر | پیش‌فرض `gemini-2.0-flash` |
| `APP_PASSWORD` | خیر، اما توصیه می‌شود | رمز انتخابی شما برای محافظت از سهمیه |

متغیرها را حداقل برای **Production** تنظیم کنید. اگر آدرس Preview هم استفاده می‌کنید، برای **Preview** نیز اضافه کنید. رمز اپ رمز گوگل/یوتیوب نیست. هیچ کلیدی در UI وارد نمی‌شود.

اگر رمز تعریف کنید، کاربر آن را بالای اپ وارد می‌کند. UI رمز را با هدر `X-App-Password` می‌فرستد تا داخل URL و تاریخچه نیاید. API پارامتر `pass` را هم برای سازگاری قبول می‌کند؛ استفاده از آن در لینک عمومی توصیه نمی‌شود.

### ۶. استفاده و افزودن به صفحهٔ اصلی

1. آدرس HTTPS اپ را باز کنید.
2. بازار، زبان محتوا، **منطقهٔ زمانی خودتان** و در صورت نیاز رمز اپ را وارد کنید. منطقهٔ زمانی پیش‌فرض از مرورگر گرفته می‌شود و قابل تغییر است، مثل `Asia/Tehran` یا `Europe/Amsterdam`.
3. دکمهٔ قرمز **🔍 تحلیل کن** را بزنید؛ جمع‌آوری داده و ساخت ایده تا حدود ۳۰ ثانیه طول می‌کشد.
4. تایم طلایی، روزهای برتر، نمودار و مدارک هر ایده را ببینید؛ عنوان/کپشن/سناریو را با دکمه‌های کپی بردارید.
5. تاریخ دقیق شمسی و ساعت هر ایده پیشنهاد انتشار است. خودتان در **YouTube Studio** زمان‌بندی کنید. این اپ چیزی آپلود نمی‌کند.
6. **آیفون، Safari:** Share → Add to Home Screen → Add.
7. **اندروید، Chrome:** منوی ⋮ → Add to Home screen یا Install app.

فایل manifest و آیکن SVG برای حالت مستقل وجود دارد؛ نمایش دکمهٔ نصب و آیکن به مرورگر بستگی دارد. آیکن SVG برای Apple Touch Icon در بعضی نسخه‌های iOS ممکن است پشتیبانی نشود و سیستم تصویر خودکار بسازد. این نسخه Service Worker و کش آفلاین صفحه ندارد؛ بنابراین بارگذاری سرد آفلاین تضمین نمی‌شود. در بارگذاری آنلاین، آخرین نتیجه از `localStorage` فوراً بازمی‌گردد. اگر زمان‌های قبلی گذشته باشند، زمان‌بندی آینده دوباره محاسبه می‌شود و **این به معنی تازه شدن دادهٔ یوتیوب نیست**.

## روش تحلیل

### جمع‌آوری فقط از API رسمی

1. `videos.list` با `chart=mostPopular`، `regionCode`، `maxResults=50` و حداکثر ۴ صفحه: تا ۲۰۰ شناسه.
2. هم‌زمان دو `search.list` با `q=#shorts` و `q=shorts`، هر کدام ۵۰ نتیجه، `type=video`، `videoDuration=short`، `order=viewCount`، `publishedAfter` هفت روز قبل، `regionCode` و `relevanceLanguage`.
3. حذف تکراری‌ها؛ حداکثر ۳۰۰ شناسه. دریافت جزئیات در دسته‌های ۵۰تایی با `part=snippet,statistics,contentDetails`.
4. فیلتر مدت **۱ تا ۱۸۰ ثانیه**، سن **حداکثر ۱۴ روز**، **حداقل ۱۰۰۰ بازدید**.
5. اگر کمتر از ۱۰ ویدیو باقی بماند: خطای فارسی «داده کافی نیست» و **بدون ساخت ایده**. نتیجهٔ قبلی، در صورت وجود، با زمان قبلی روی صفحه می‌ماند.

فقط درخواست‌های رسمی YouTube Data API برای جمع‌آوری ویدیو استفاده می‌شود؛ scraping، دیتاست ثابت یا دادهٔ نمایشی در مسیر production وجود ندارد.

### امتیازدهی

```text
ageH = max(hours since publication, 1)
vph = views / ageH
eng = (likes + 2 × comments) / views
score = log10(vph + 1) × (1 + min(eng, 0.2) × 5)
```

نبود like/comment برابر صفر در نظر گرفته می‌شود. بازدید منفی و تاریخ انتشار آینده حذف می‌شوند؛ لایک/کامنت منفی صفر در نظر گرفته می‌شوند.

### استخراج ترند

- فقط تگ‌ها و هشتگ‌های عنوان/توضیح، با حروف یونیکد و فارسی؛ کوچک‌سازی حروف، NFKC، یکسان‌سازی ی/ک و تبدیل عبارت چندکلمه‌ای به `_`.
- حذف کلمات کم‌ارزش، سال‌ها/اعداد مستقل و حروف ربط رایج.
- حداقل **۳ کانال متفاوت** و حداقل **۱ ویدیو در ۷۲ ساعت اخیر**.
- اگر حداقل ۴۰٪ ویدیوهای موضوع تازه باشند «در اوج»، در غیر این صورت «هنوز زنده».
- امتیاز کل، تعداد کانال/ویدیو/تازه‌ها، میانهٔ ویو بر ساعت، تا ۴ هشتگ همراه موجود و ۳ ویدیوی برتر با لینک رسمی.
- تکرار یکسان مجموعهٔ سه مدرک حذف می‌شود. حداکثر ۶ موضوع. تشابه معنایی فراتر از تطابق کلیدواژه ادعا نمی‌شود.
- اگر ویدیوی معتبر کافی باشد اما موضوع واجد شرایط پیدا نشود، فقط برآورد زمان و پیام شفاف نمایش داده می‌شود؛ ترند یا ایدهٔ جعلی نمی‌سازیم.

### تایم طلایی

- انتخاب ۴۰٪ برتر با گرد کردن رو به بالا، حداقل ۱۵ ویدیو (اگر کل داده ۱۰ تا ۱۴ بود، همهٔ دادهٔ موجود).
- تبدیل زمان انتشار با `Intl.DateTimeFormat` و منطقهٔ زمانی انتخابی؛ هیستوگرام وزن‌دار با `score`، نرم‌سازی ساعت قبل و بعد با ضریب ۰٫۵ و چرخش در نیمه‌شب.
- ساعت اول، ساعت دوم با **فاصلهٔ چرخشی حداقل ۴ ساعت** و ۳ روز هفته با بالاترین مجموع امتیاز.
- اطمینان بر اساس **اندازهٔ نمونهٔ برتر انتخاب‌شده**: حداقل ۶۰ = بالا، حداقل ۳۰ = متوسط، کمتر = پایین. این یک برچسب ابتکاری است، نه فاصلهٔ اطمینان آماری.
- میانگین مدت ویدیوهای نمونهٔ برتر.

### ایده و برنامهٔ انتشار

Gemini فقط JSON با `responseMimeType=application/json` دریافت می‌کند و دستور صریح منع شایعه/خبر، محتوای اورجینال و نبود موسیقی دارای کپی‌رایت دارد. بدون کلید، روی خطا، JSON نامعتبر یا سناریوی با زمان‌بندی خراب، قالب فارسی ۱۲ ثانیه‌ای ۵ بیتی استفاده می‌شود. خطای AI مانع تحلیل داده نیست. در حالت قالبی، زبان انتخابی فقط روی جست‌وجو اثر دارد و متن ایده فارسی می‌ماند.

مدت ۱۰ تا ۱۵، عنوان زیر ۶۰ کاراکتر، بیت‌های پیوسته از صفر تا پایان، قلاب ۰–۲، کپشن سوال‌دار، `#shorts` اجباری و حداکثر ۵ هشتگ بدون فاصله سمت سرور کنترل می‌شوند. صدا برای ایمنی به ضبط شخصی و افکت ساخت خود کاربر محدود است. دلیل ایده با **اعداد سرور** ساخته می‌شود، نه عدد تولیدشده توسط AI. پایان لوپ در دستور/قالب آمده؛ کیفیت و صحت معنایی متن AI نیاز به بررسی انسان دارد.

ایده‌های فرد در ساعت اول و زوج در ساعت دوم؛ اولویت با روزهای برترِ پیش رو، ترتیب زمانی صعودی، فاصلهٔ مطلق حداقل چهار ساعت (حتی هنگام تغییر ساعت تابستانی)، حداکثر سه مورد در یک روز و تاریخ شمسی. تبدیل ساعت محلی با اختلاف‌های نیم‌ساعته و DST سازگار است؛ ساعت محلی ناموجود در تغییر ساعت رد می‌شود. ثبت انتشار فقط دستی در Studio است.

## سهمیه و کش

با هزینهٔ متداول `search.list=100` و `videos.list=1` واحد:

```text
۲ جست‌وجو × ۱۰۰                = ۲۰۰ واحد
تا ۴ صفحهٔ mostPopular × ۱      =   ۴ واحد
تا ۶ دستهٔ جزئیات × ۱          =   ۶ واحد
حداکثر معمول هر تحلیل تازه     = ۲۱۰ واحد از ۱۰٬۰۰۰ واحد روزانه
```

تقریباً **۴۷ تحلیل کامل بدون کش** در روز در سقف ۱۰٬۰۰۰ واحد (بقیهٔ مصرف پروژه، خطاها، درخواست‌های هم‌زمان و تغییر قوانین سهمیه را در نظر بگیرید). هر بار کلیک الزاماً ۲۱۰ واحد مصرف نمی‌کند؛ تعداد صفحه‌ها و برخورد به کش مؤثر است. سهمیه معمولاً در نیمه‌شب زمان Pacific بازنشانی می‌شود، نه تهران.

بدون رمز، پاسخ موفق هدر زیر دارد:

```http
Cache-Control: s-maxage=1800, stale-while-revalidate=3600
```

CDN در صورت پذیرش کش، تا ۳۰ دقیقه پاسخ مشترک برای پارامترهای یکسان می‌دهد و ممکن است تا ۶۰ دقیقهٔ دیگر نسخهٔ قبلی را هنگام بازاعتبارسنجی نشان دهد. زمان واقعی جمع‌آوری روی صفحه دیده می‌شود. زبان، بازار و منطقهٔ زمانی متفاوت کش متفاوت دارند. کش CDN best-effort است، نه تضمین سهمیه؛ مرورگر شخصی هم آخرین نتیجه را ذخیره می‌کند، اما کلیک تازه درخواست جدید می‌فرستد.

**استثنای امنیتی عمدی:** وقتی `APP_PASSWORD` فعال است، پاسخ `private, no-store` است تا کش مشترک نتواند احراز رمز را دور بزند یا بعد از تغییر رمز جواب قبلی بدهد. در این حالت هر تحلیل تازه سهمیه مصرف می‌کند؛ برای صرفه‌جویی از آخرین نتیجه استفاده کنید. پاسخ‌های خطا همیشه `no-store` هستند. اگر قبلاً بدون رمز دیپلوی کرده‌اید، بعد از فعال کردن رمز دیپلوی جدید انجام دهید و کش عمومی دیپلوی قبلی را از Vercel پاک/آدرس قبلی را غیرفعال کنید.

این نسخه محدودکنندهٔ نرخِ سراسری ندارد چون state مشترک/دیتابیس ندارد. روی URL عمومی بدون رمز، دیگران هم می‌توانند سهمیه را مصرف کنند. درخواست‌های هم‌زمان cache miss نیز ممکن است چند تحلیل بسازند. رمز قوی بگذارید و آن را منتشر نکنید؛ یک درخواست هم‌زمان در هر صفحه کنترل می‌شود، نه کل سرویس.

## API

```http
GET /api/analyze?region=US&lang=fa&tz=Asia%2FTehran&pass=...
```

پیشنهاد امن‌تر (برای استفادهٔ برنامه‌ای):

```sh
curl -H 'X-App-Password: YOUR_APP_PASSWORD' \
  'https://YOUR-APP.vercel.app/api/analyze?region=US&lang=fa&tz=Asia%2FTehran'
```

- بازارها: `US, GB, CA, DE, TR, AE, SA, IQ, AF, IN, FR, AU`
- زبان‌ها: `fa, en, ar, tr, de`
- منطقهٔ زمانی: شناسهٔ IANA معتبر. پیش‌فرض مستقیم API: `Asia/Tehran`.
- خروجی موفق: `version, generatedAt, region, lang, timezone, stats, golden, trends, ideas, ideaMode, message`.
- خطا: `{ "error": "پیام فارسی ساده", "code": "MACHINE_CODE" }`.
- وضعیت‌ها: `400` ورودی نامعتبر، `401` رمز اشتباه، `405` متد نامعتبر، `422` داده ناکافی، `503` کلید تنظیم نشده، `502` خطای اتصال یا API یوتیوب.
- مهلت کل داخلی حدود ۲۷ ثانیه، تلاش AI حداکثر ۸٫۵ ثانیه در همین مهلت؛ تابع Vercel حداکثر ۳۰ ثانیه، مرورگر ۳۲ ثانیه صبر می‌کند.

## حریم خصوصی و امنیت

- کلیدهای سرویس فقط سمت سرور؛ هیچ secret در manifest، HTML یا پاسخ API نیست.
- تنظیمات **از جمله رمز اپ** و آخرین نتیجه طبق طراحی در localStorage ذخیره می‌شوند؛ localStorage رمزنگاری امنِ رمز نیست. روی دستگاه مشترک دکمهٔ «پاک کردن داده‌های این دستگاه» را بزنید.
- API و CDN ممکن است کش موقت نتیجه داشته باشند؛ هیچ دیتابیس یا ذخیرهٔ دائمی سمت سرور توسط اپ وجود ندارد. زیرساخت سرویس‌دهنده ممکن است log استاندارد درخواست‌ها را نگه دارد؛ برای رمز از هدر استفاده کنید.
- تمام متن‌های API پیش از HTML escape یا با `textContent` نمایش داده می‌شوند؛ لینک مدرک فقط الگوی HTTPS دامنهٔ رسمی یوتیوب با شناسهٔ ۱۱ کاراکتری را قبول می‌کند. خروجی عددی نمودار اعتبارسنجی می‌شود.
- متن تولیدشدهٔ AI هم غیرقابل اعتماد است. دستور ضد prompt injection وجود دارد ولی تضمین صحت محتوا نیست؛ بازبینی انسانی لازم است.
- هیچ فونت، اسکریپت، تحلیل‌گر یا CDN خارجی از مرورگر بارگیری نمی‌شود؛ فونت Tahoma/سیستمی است.

## اجرای محلی و تست (اختیاری؛ نیاز به کامپیوتر/محیط Node)

```sh
cp .env.example .env
# فقط روی دستگاه خودتان .env را با کلیدهای واقعی پر کنید.
npm run dev
# http://localhost:3000
npm test
npm run check
```

نیازی به نصب پکیج نیست. سرور توسعه فقط چهار فایل عمومی و endpoint تحلیل را سرو می‌کند و `.env` را روی وب افشا نمی‌کند. روی `0.0.0.0` با پورت پیش‌فرض ۳۰۰۰ اجرا می‌شود. مرورگر از مسیر نسبی `/api/analyze` استفاده می‌کند؛ HTTPS و کپی کلیپ‌بورد در Vercel کار می‌کنند، برای HTTP شبکهٔ محلی روش جایگزین کپی وجود دارد.

تست‌ها شبکهٔ YouTube/Gemini را **mock** می‌کنند؛ داده‌های ساختگی فقط داخل تست‌اند و هیچ دکمهٔ دموی جعلی در اپ وجود ندارد. فیلترها، فرمول امتیاز، شروط ترند، حذف تکرار مدرک، سهمیهٔ ۲۱۰، زمان/روز و DST، فاصلهٔ آپلودها، XSS، احراز رمز، کش و خطاهای سرویس بررسی می‌شوند. آزمون زندهٔ سرویس‌های Google نیازمند کلیدهای خودتان و اینترنت سرور است.
